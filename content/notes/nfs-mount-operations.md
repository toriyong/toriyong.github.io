## 개요

NFS 로 스토리지를 붙여 쓸 때의 마운트 옵션 선택과, 운영 중 가장 자주 만나는 멈춤·끊김 현상의 처리 방법이다.

## 배경

NFS 는 쉽게 붙지만, 옵션을 기본값으로 두면 서버가 통째로 멈추는 상황을 만든다. 옵션 중 성격을 결정하는 건 두 개다.

| 옵션 | 서버가 응답 없을 때 | 쓰는 곳 |
| --- | --- | --- |
| `hard` (기본) | 될 때까지 무한 재시도, 프로세스가 D 상태로 멈춤 | 데이터 무결성이 중요한 곳 |
| `soft` | 타임아웃 후 I/O 오류 반환 | 읽기 전용, 중단돼도 되는 곳 |

`hard` 가 기본이고 대부분 맞다. `soft` 는 쓰기 중 타임아웃이 나면 **데이터가 깨질 수 있다.** 그래서 쓰기가 있는 마운트에는 쓰지 않는다.

대신 `hard` 는 NFS 서버가 죽으면 그 경로에 접근한 프로세스가 전부 묶인다. `df` 조차 멈춘다. 이걸 완화하는 게 `intr`(최신 커널에서는 기본 동작) 과 타임아웃 조정이다.

## 마운트

```
# /etc/fstab
<서버>:/export/data  /data  nfs4  rw,hard,_netdev,noatime,rsize=1048576,wsize=1048576,timeo=600,retrans=2  0 0
```

옵션 설명이다.

- `_netdev` — 네트워크가 올라온 뒤 마운트한다. **빠뜨리면 부팅이 멈춘다.**
- `noatime` — 읽기마다 접근 시각을 쓰지 않는다. NFS 에서는 효과가 크다
- `rsize`/`wsize` — 한 번에 주고받는 크기. 1MB 가 일반적
- `timeo=600` — 60초(1/10초 단위). `retrans=2` 와 함께 재시도 간격을 정한다

```
mount -a
mount | grep nfs
nfsstat -m          # 실제 적용된 옵션 확인
```

`nfsstat -m` 이 중요하다. 쓴 대로 적용되지 않는 옵션이 있다.

## 자주 만나는 문제

### Stale file handle

서버 쪽에서 export 를 다시 만들거나 파일시스템이 바뀌면 난다. 클라이언트가 들고 있던 핸들이 무효가 된 것이다.

```
umount -f /data      # 안 되면
umount -l /data      # lazy, 참조가 끝나면 해제
mount /data
```

`umount -l` 은 즉시 떼어낸 것처럼 보이지만 실제로는 참조가 끝날 때 해제된다. 임시방편이고, 해당 경로를 쓰던 프로세스는 재시작해야 정상으로 돌아온다.

### 접근하면 멈춘다

NFS 서버나 네트워크가 끊긴 상태다. 확인부터 한다.

```
# 멈추지 않게 보려면
timeout 5 df -h /data || echo "응답 없음"

# 서버 쪽 응답 확인
rpcinfo -t <서버> nfs
showmount -e <서버>

# 묶여 있는 프로세스
ps -eo pid,stat,wchan:30,cmd | awk '$2 ~ /D/'
```

D 상태(uninterruptible sleep) 프로세스는 `kill -9` 로도 안 죽는다. NFS 가 돌아와야 풀린다. 그래서 복구 순서는 **NFS 서버를 살리는 것이 먼저**다.

### 권한이 이상하다

NFSv4 는 사용자를 이름으로 매핑한다. 클라이언트와 서버의 도메인 설정이 다르면 전부 `nobody` 로 보인다.

```
# /etc/idmapd.conf 의 Domain 이 양쪽 동일해야 한다
grep -i domain /etc/idmapd.conf
nfsidmap -c         # 캐시 비우기
```

## 운영 시 주의

- **같은 파일시스템을 여러 서버에서 동시에 쓰기로 마운트할 때**는 애플리케이션이 그걸 전제로 설계돼 있어야 한다. 락 처리가 없으면 깨진다.
- NFS 서버를 재기동할 때는 클라이언트 영향 범위를 먼저 파악한다. `hard` 마운트가 걸린 서버들이 그 시간 동안 멈춘다.
- 백업 대상에 NFS 마운트 경로가 들어가면, 백업이 NFS 를 타고 돌면서 느려지거나 중복 백업이 된다. 제외 설정을 확인한다.
- 방화벽은 NFSv4 면 2049 하나로 충분하다. v3 는 portmapper 때문에 포트가 여럿 필요해 더 복잡하다. 가능하면 v4 를 쓴다.

## 실무 권장

- fstab 에 넣기 전에 `mount -o <옵션>` 으로 먼저 붙여 본다. fstab 오류는 다음 부팅 때 터진다.
- `_netdev` 누락은 재부팅 전까지 모른다. 작업 후 **계획된 재부팅으로 한 번 검증**한다.
- 마운트 경로별로 용도·서버·옵션을 표로 관리한다. 장애 때 어느 서버가 영향받는지 즉시 나온다.
