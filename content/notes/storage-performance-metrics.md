## 개요

스토리지가 느리다는 말이 나왔을 때 무엇을 재고 어떻게 읽을지 정리한 것이다. IOPS 숫자 하나만 보면 판단이 안 된다.

## 배경

스토리지 성능은 네 가지가 서로 맞물린다. 하나만 보면 틀린 결론이 나온다.

| 지표 | 의미 | 주로 영향받는 작업 |
| --- | --- | --- |
| IOPS | 초당 I/O 횟수 | 작고 랜덤한 I/O (DB) |
| 처리량(MB/s) | 초당 데이터량 | 크고 순차적인 I/O (백업, 복사) |
| 지연(latency) | I/O 하나가 끝나는 데 걸린 시간 | 체감 성능 |
| 큐 깊이 | 대기 중인 I/O 수 | 포화 여부 |

**체감은 지연이 결정한다.** IOPS 가 높아도 지연이 길면 사용자는 느리다고 느낀다. 그리고 IOPS 와 지연은 맞바꾸는 관계다. 큐를 깊게 쌓으면 IOPS 는 올라가지만 하나하나의 지연은 길어진다.

## 측정

```
# 장치별 현황 — 1초 간격
iostat -xz 1

# 주요 열
#  r/s, w/s      초당 읽기·쓰기 횟수 (IOPS)
#  rkB/s, wkB/s  처리량
#  r_await       읽기 평균 지연 (ms)
#  w_await       쓰기 평균 지연 (ms)
#  aqu-sz        평균 큐 길이
#  %util         장치가 바빴던 시간 비율
```

`%util` 은 SSD·SAN 에서는 의미가 약하다. 병렬 처리가 되기 때문에 100% 라도 여유가 있을 수 있다. **`await` 와 `aqu-sz` 를 함께 본다.**

어느 프로세스가 쓰고 있는지는 따로 본다.

```
iotop -oPa          # 누적으로 보기
pidstat -d 1
```

## 읽는 법

| 관찰 | 해석 |
| --- | --- |
| await 높음 + aqu-sz 낮음 | 장치 자체가 느림 (디스크·경로·스토리지) |
| await 높음 + aqu-sz 높음 | 부하가 수용량을 넘음 (경합) |
| %util 100% + await 정상 | 바쁘지만 버티는 중 — 정상일 수 있음 |
| r/s 는 적은데 rkB/s 가 큼 | 큰 순차 읽기 — 백업·복사 중일 가능성 |
| r/s 많고 rkB/s 작음 | 작은 랜덤 I/O — DB 패턴 |

지연 기준은 매체마다 다르다. 회전 디스크는 10~20ms 도 정상, SSD 는 1ms 를 넘으면 의심, SAN 은 5ms 안팎이 보통이다. **중요한 건 절대값이 아니라 평소 대비 변화**다.

## 성능 측정이 필요할 때

도입·증설 전에 기준치를 재려면 `fio` 를 쓴다.

```
# 랜덤 읽기 IOPS (DB 유사)
fio --name=randread --rw=randread --bs=4k --iodepth=32 --numjobs=4 \
    --size=4G --runtime=60 --time_based --group_reporting \
    --filename=/data/fiotest

# 순차 쓰기 처리량 (백업 유사)
fio --name=seqwrite --rw=write --bs=1M --iodepth=8 --numjobs=1 \
    --size=8G --runtime=60 --time_based --group_reporting \
    --filename=/data/fiotest
```

**운영 중인 서버에서 돌리지 않는다.** 다른 작업이 전부 느려진다. 테스트 후 생성된 파일은 지운다.

## 운영 시 주의

- 캐시 때문에 측정값이 실제보다 좋게 나올 수 있다. `--direct=1` 을 주거나 테스트 크기를 메모리보다 크게 잡는다.
- 가상화 환경에서는 게스트에서 잰 값이 호스트 경합을 반영하지 못한다. 호스트 쪽 지표를 함께 본다.
- 공유 스토리지는 **다른 서버의 부하**가 내 성능을 깎는다. 내 서버만 봐서는 원인이 안 나온다. 스토리지 콘솔에서 전체 부하를 본다.
- 스냅샷·복제·중복 제거가 도는 시간대는 성능이 떨어진다. 작업 창을 확인한다.

## 실무 권장

- 평소 지표를 기록해 둔다. 비교 대상이 없으면 "느리다"를 증명할 수 없다.
- 용량 증설 요청에는 **IOPS·지연 요구치**를 같이 적는다. 용량만 맞추면 성능이 모자라는 구성이 나온다.
- DB 서버와 백업 대상은 같은 LUN·데이터스토어에 두지 않는다. 백업 시간에 DB 가 느려지는 원인 1순위다.
