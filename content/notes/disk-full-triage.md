## 개요

파일시스템이 가득 찼을 때 원인을 찾아 복구하는 순서다. 급하다고 아무 파일이나 지우면 서비스가 더 망가진다.

## 배경

`df` 는 가득 찼다고 하는데 `du` 로 더해 보면 용량이 안 맞는 경우가 흔하다. 원인은 보통 셋 중 하나다.

| 증상 | 원인 | 확인 |
| --- | --- | --- |
| df 와 du 차이가 큼 | 지웠지만 프로세스가 붙잡고 있는 파일 | `lsof +L1` |
| 용량은 남는데 쓰기 실패 | inode 고갈 | `df -i` |
| 특정 디렉터리만 안 보임 | 마운트에 가려진 파일 | 마운트 해제 후 확인 |

삭제된 파일을 프로세스가 열고 있으면, 디렉터리 엔트리만 사라지고 블록은 그대로 남는다. 로그 파일을 `rm` 으로 지웠는데 공간이 안 느는 전형적인 경우다.

## 진단

```
# 1) 어디가 찼는지
df -hT
df -i                       # inode 도 함께 본다

# 2) 큰 디렉터리 찾기 (한 파일시스템 안에서만)
du -xh --max-depth=1 / 2>/dev/null | sort -h | tail -20

# 3) 지워졌는데 잡혀 있는 파일
lsof +L1 | sort -k7 -n | tail
```

`du` 에 `-x` 를 붙이는 이유는, 안 붙이면 다른 마운트까지 타고 들어가 엉뚱한 곳을 센다.

## 조치

**삭제됐는데 잡혀 있는 파일**은 해당 프로세스를 재시작하거나, 재시작이 어려우면 파일 디스크립터를 비운다.

```
# lsof 결과의 PID 와 FD 번호로
: > /proc/<PID>/fd/<FD>
```

이건 파일 내용을 비우는 것이지 파일을 지우는 게 아니다. 프로세스는 계속 쓸 수 있다.

**로그가 범인일 때**는 `rm` 대신 비운다. 프로세스가 붙잡고 있어도 바로 반영된다.

```
: > /var/log/<파일>
```

근본 조치는 logrotate 다. 안 돌고 있으면 설정부터 본다.

```
logrotate -d /etc/logrotate.conf    # -d 는 모의 실행
```

**inode 고갈**은 작은 파일이 수십만 개 쌓인 디렉터리가 원인이다. 세션 파일, 캐시, 메일 큐를 본다.

```
for d in /var/* /tmp; do echo "$(find $d -xdev 2>/dev/null | wc -l) $d"; done | sort -rn | head
```

## 운영 시 주의

- **`/var/log` 밑을 통째로 지우지 않는다.** 감사 추적이 사라지고, 침해 사고 때 조사할 근거가 없어진다. 오래된 것부터 압축해 옮긴다.
- `/tmp` 도 함부로 비우지 않는다. 애플리케이션이 소켓이나 락 파일을 거기 두는 경우가 있다.
- root 예약 공간(기본 5%) 덕분에 일반 사용자만 실패하고 root 는 쓰기가 되는 구간이 있다. `tune2fs -m 1` 로 줄일 수 있지만, 급한 불을 끌 때만 쓰고 원복한다.
- `/` 가 100% 면 로그인 자체가 안 될 수 있다. 콘솔 접근 경로를 확보하고 작업한다.

## 실무 권장

- 디스크 사용률은 **추세**로 본다. 85% 경고보다 "하루 3% 씩 증가"가 더 유용하다.
- 용량 큰 로그는 별도 파일시스템으로 분리한다. 로그가 차도 루트는 산다.
- 긴급 조치 후 반드시 원인을 정리한다. 지우고 끝내면 같은 일이 반복된다.
