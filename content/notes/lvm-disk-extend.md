## 개요

운영 중인 리눅스 서버의 디스크가 찼을 때, 서비스를 내리지 않고 늘리는 절차다. LVM 으로 구성되어 있으면 디스크 추가 → PV 생성 → VG 확장 → LV 확장 → 파일시스템 확장 순서로 무중단 처리가 된다.

## 배경

LVM 은 물리 디스크(PV)를 묶어 볼륨 그룹(VG)을 만들고, 거기서 논리 볼륨(LV)을 잘라 쓰는 구조다. 이 한 겹 덕분에 디스크를 붙이면 기존 파일시스템을 그대로 둔 채 용량만 늘릴 수 있다.

LVM 이 아닌 일반 파티션이면 이 방법을 쓸 수 없다. 파티션 테이블을 직접 손봐야 하고 위험도가 훨씬 높다.

## 확인

작업 전에 현재 구성을 먼저 본다.

```
df -hT                     # 어느 마운트가 찼는지, 파일시스템 종류
lsblk                      # 디스크와 파티션 구조
pvs ; vgs ; lvs            # LVM 구성과 여유 공간
vgdisplay vg_data | grep Free
```

`vgs` 의 VFree 에 여유가 있으면 디스크 추가 없이 4번부터 하면 된다.

## 절차

1. 가상 환경(vSphere, Azure, OCI)에서 디스크를 추가하거나 기존 디스크를 늘린다.
2. OS 가 새 디스크를 인식하게 한다.

```
echo "- - -" > /sys/class/scsi_host/host0/scan     # 호스트마다 반복
lsblk                                               # 새 디스크(sdc 등) 확인
```

기존 디스크를 늘린 경우에는 해당 장치만 다시 읽는다.

```
echo 1 > /sys/class/block/sdb/device/rescan
```

3. PV 를 만들고 VG 에 붙인다.

```
pvcreate /dev/sdc
vgextend vg_data /dev/sdc
vgs                                                 # VFree 증가 확인
```

4. LV 를 늘린다. 여유를 전부 쓰려면 `+100%FREE`.

```
lvextend -l +100%FREE /dev/vg_data/lv_data
```

5. 파일시스템을 늘린다. 종류에 따라 명령이 다르다.

```
resize2fs /dev/vg_data/lv_data        # ext4
xfs_growfs /data                      # xfs — 마운트 지점을 넘긴다
```

6. 확인한다.

```
df -hT /data
```

`lvextend -r` 를 쓰면 4번과 5번을 한 번에 한다. 다만 파일시스템 종류를 자동 판단하므로, 중요한 서버에서는 나눠서 확인하며 진행하는 편이 안전하다.

## 운영 시 주의

- **xfs 는 줄일 수 없다.** 한 번 늘리면 되돌릴 방법이 없으니 필요한 만큼만 늘린다.
- 작업 전 스냅샷이나 백업 상태를 확인한다. 명령 자체는 안전하지만 디스크를 잘못 지정하면 복구가 어렵다.
- 디스크를 잘못 고르는 사고가 가장 많다. `pvcreate` 전에 `lsblk` 로 해당 장치에 아무것도 없는지 반드시 본다.
- 멀티패스 환경이면 `/dev/sdX` 가 아니라 `/dev/mapper/mpathX` 를 대상으로 한다.
- VG 에 디스크를 섞어 넣으면 나중에 특정 디스크만 빼기 어려워진다. 성능 등급이 다른 디스크는 VG 를 나눈다.

## 실무 권장

- 디스크는 한 번에 크게 붙이기보다 여유를 두고 단계적으로 늘린다. VG 에 여유를 남겨 두면 다음 증설이 LV 확장 한 줄로 끝난다.
- 증설 이력(날짜, 대상, 증설 전후 용량, 사유)을 남긴다. 반복해서 차는 서버는 증설이 아니라 원인(로그 미삭제, 덤프 누적)을 봐야 한다.
- 80% 를 넘기면 알림이 오도록 모니터링을 걸어 두고, 90% 에서 급하게 작업하는 상황을 만들지 않는다.
